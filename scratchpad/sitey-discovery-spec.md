## 할 일

### 1. 🔴 `public/.well-known/mcp.json` 이 낡았다 — 이게 1순위다

지금 내용이 **사실과 다르다.** 공개된 거짓 정보다.

```json
{
  "name": "sitey.one",                          // 정본은 sitey.my 다
  "url": "https://sitey.one/mcp",               // 정본 아님
  "description": "... 3 subdomains max ...",    // 실제 기본 한도는 5
  "authentication": { "... With API key: unlimited." }   // unlimited 아니다. 한도제 + 초과분 유료
}
```

**고칠 것**
- 이름·URL 을 **정본 도메인**으로. ⚠️ **문자열을 코드에 박지 마라** — 정본은 `config.server.publicOrigin` 에 있다(2026-09-11 에 같은 이유로 고쳤다). 빌드 시점에 생성하든 런타임에 서빙하든, **정본이 바뀌면 따라가야 한다.**
- 한도 설명을 **실제 설정값**과 맞춘다. 기본 한도·예외·갱신 주기(사람 3개월 / 에이전트 1개월)는 코드·마이그레이션이 정본이다. **문서에 적힌 값을 믿지 말고 코드에서 읽어라** (2026-09-09 에 위키엔 7일, 코드엔 1개월이었다).
- 발급 도메인이 **넷**이다(`sitey.my`·`sitey.one`·`officials.my`·`officials.one`). `managed_domains` 에서 읽는다.

### 2. OpenAPI 스펙 — 단일 최대 효과

- `routes/api-v1.js` 의 **실제 라우트에서** 스펙을 만든다. 손으로 쓴 문서를 만들지 마라 — 코드와 갈라진다.
- `/openapi.json` 으로 서빙한다. `/docs` 페이지에서 링크한다.
- ⚠️ `public/robots.txt` 가 `/api/` 를 막고 있다. **스펙 파일 자체는 크롤러가 읽을 수 있어야 한다** — 경로를 `/api/` 밖에 두거나 robots 에 예외를 둔다. 어느 쪽이든 **이유를 커밋 메시지에 적어라.**
- 오류 응답도 스펙에 넣는다. 에이전트에게는 **오류 모양이 곧 인터페이스**다.

### 3. `llms.txt`

- `/llms.txt` 로 서빙. 사이트가 뭘 하는지·어떻게 부르는지·한도가 뭔지 **평문으로**.
- OpenAPI·MCP 엔드포인트를 여기서 가리킨다.
- 여기도 **정본 도메인을 코드에 박지 마라.**

### 4. `sitemap.xml` 점검

지금 있는 것이 실제 페이지와 맞는지 확인만 하고, 틀린 것만 고친다. **없는 페이지를 지어내 넣지 마라.**
